# Sales module — demo script per slice

Local: `npm run seed` then `npm run dev`; sample accounts use `Sample12345!` (see README). Staging: `seedStagingDemo` returns the passwords once.

## S1 — قاعدة بيانات المبيعات [SAL §17 المرحلة الأولى] (built 2026-11-12)

Accounts: **sultan@eayni.local** (مدير المبيعات: department manager of Sales, Sales-manager rights implied), **reem@eayni.local** and **majed@eayni.local** (موظفو مبيعات), **arwa@eayni.local** (خدمة العملاء), **abdullah@eayni.local** (الإدارة التنفيذية, read-only).

1. **Rep (reem)** → menu «المبيعات» → «الواجهة الرئيسية للمبيعات»: counters for my customers, follow-ups due today, open and overdue opportunities, leads assigned to me. Button «الخدمات» lists the seven services (screens arrive in S2).
2. «عميل جديد / فرصة بيعية جديدة»: type «شركة الخليج» in the name — the duplicate warning appears while typing (reem owns it, so the number shows). Type «مصنع الشرق للحديد» — only «هذه الجهة مسجلة لدى موظف آخر — راجع مدير القسم» (majed's file never leaks). Fill a new organization with 3 contacts (the 4th «إضافة» button disappears) and tick «إضافة فرصة بيعية»; save → the customer file opens.
3. **Customer file**: tabs سجل التواصل / الأشخاص المسؤولون / الفرص البيعية / بيانات الجهة / السجل. On a phone (375 px) the log composer sits under the log: pick «زيارة», write details, set «موعد المتابعة القادمة», attach a photo, save. The entry shows your name and the time; there is no edit or delete.
4. **Pipeline** «الفرص البيعية»: Kanban by the eight stages (column totals in SAR), table view, filters by stage / service / tag / follow-up overdue. Open «تأجير حاويات لمعرض» (lost) to see the reason; move another opportunity to «خاسرة» without a reason → refused; pick a reason from the provisional list.
5. **Manager (sultan)** → «العملاء»: sees both reps' files; filter by «الموظف المسؤول»; select several and «نقل … عميل» with a reason → both reps get notifications («إسناد عميل إلى موظف» / «تغيير الموظف المسؤول»); the file's «السجل» tab shows the transfer with the reason. «إدارة التصنيفات»: add «#منطقة_الشرقية», rename it, see the records follow. In a file's «بيانات الجهة» set «تصنيف العميل» (reps cannot).
6. **Customer Service (arwa)** → «إحالة عميل محتمل إلى المبيعات»: fill «مطعم النخيل» → sultan receives «وصول عميل جديد من خدمة العملاء». Arwa's list shows what Sales did with each referral.
7. **Manager** → «العملاء المحتملون»: the seeded «مجمع الواحة السكني» carries the red «متأخر عن التسجيل» badge (referred 30 h ago, 24 h rule); assign the new lead to reem → reem gets «إسناد عميل إلى موظف».
8. **Rep (reem)** → «العملاء المحتملون» → «المسندون إليّ» → open the lead → «تحويل إلى عميل» with an opportunity → a customer with source «خدمة العملاء», linked to the lead (file tab «بيانات الجهة» → «محال من خدمة العملاء»).
9. **Executive (abdullah)**: «العملاء» and «الفرص البيعية» list everything, read-only (no «عميل جديد» button; the API refuses creation).
10. **Admin** → «الإعدادات» → groups «إدارة العملاء (CRM)» and «المبيعات»: the 24-hour setting, organization types, provisional facility sizes and loss reasons, follow-up reminder hours. «الأدوار والصلاحيات»: `sales_rep` / `sales_manager` are editable system roles; editing your own role is refused.

## S2 — إدارة الخدمات والطلبات [SAL §17 المرحلة الثانية] (built 2026-11-12)

Extra accounts: **nasser@eayni.local** (مدير المشتريات), **talal@** (مشتريات), **abdulaziz@** (مدير المالية, `finance_manager`), **shahad@** (`finance_staff`), **khalid@** (مدير التشغيل), **omar@** (تشغيل).

1. **Rep (reem)** → «المبيعات» → «الخدمات» lists the seven services; pick «بيع الحاويات» → the screen shows that service's own fields (lists such as نوع الحاوية are free text until the owner sends them — hint shown). Choose the customer, fill العدد, attach a file, save → the request `CSR-…` opens with «المبيعات» as holder.
2. **Request page**: «الإجراءات المتاحة لك» shows only what the workflow allows this user from this state: إعداد عرض السعر → إرسال العرض → موافقة العميل → رفع طلب إلى المشتريات. Each hop appears in «سجل انتقال الطلب بين الأقسام».
3. **Procurement (talal)** → «الطلبات الواردة من المبيعات» (menu item appears only for Procurement / Finance / Operations members): the request is there with its SLA; open it → the Sales data is read-only, the Procurement panel takes المورد + عرض المورد → «تحويل إلى المالية للاعتماد». Nasser and talal received «وصول طلب جديد إلى المشتريات».
4. **Finance (shahad)** → the request is in her queue; she may only «يحتاج استكمال بيانات» (with a reason) — the request returns to reem who «إعادة الإرسال إلى المالية». **abdulaziz** → «اعتماد»; reem and nasser get «اعتماد أو رفض الطلب من المالية». Try approving with reem's own Finance account: refused (approver ≠ creator).
5. **Procurement (nasser)**: بدأ التنفيذ → قيد المعالجة (تاريخ التسليم) → تم الإنجاز (نموذج الاستلام) → «إحالة إلى التشغيل»; reem gets «تحديث حالة الطلب من المشتريات» at each step.
6. **Operations (omar)**: the request shows OPS labels — جديد (3 business days to «مجدول», counted over Friday–Saturday and holidays; the row turns red when exceeded and the manager can add «سبب التأخر» with الجهة المسؤولة) → «جدولة الزيارة» creates a visit on the shared calendar with reem as participant → قيد التنفيذ → مكتمل with الكميات والأوزان and محاضر التسليم → reem gets «اكتمال التنفيذ من التشغيل».
7. **Rep (reem)**: «تم الإغلاق بنجاح» → Operations is notified; or «تم الإغلاق دون استكمال» (reason). Only the manager may «تم إيقاف المشروع» / «تم إلغاء المشروع».
8. **Rental (seeded `RNT-…`, at Operations, مجدول)**: omar opens it → «نموذج توثيق جديد» → اختر «نموذج قبل التسليم», photos (required), رقم الحاوية, حالة الحاوية, signature upload. Three phases, append-only, each with employee and time.
9. **Scrap (seeded `SCR-…`)**: visible to Sales and Operations from the start. Omar: «تسجيل تقييم» (photos, weight, categories, proposed price) → «تسجيل نتيجة التقييم»; majed: «الاتفاق على السعر»; omar: «جدولة السحب» → «تسجيل الوزن الفعلي ومحضر الاستلام» (Sales and Finance notified); sultan (allowed role, setting `sales.scrapTransferRoles`): «تسجيل تحويل المبلغ» with the proof file. «رفع مهمة» (khalid → omar): a task with حالة المهمة «تمت / لم تتم» and حالة تحويل المبلغ.
10. **Destruction (seeded `DST-…`, at Operations)**: omar records «تسجيل التقدير» (الوزن التقديري) → the request returns to reem at «إعداد عرض السعر»; after the customer approves → المالية → after approval → التشغيل (3 business days) → «مكتمل» requires محضر الاستلام.
11. **Asset return (seeded `ARO-…`)**: قيد الدراسة → قيد التفاوض → «لم يتم التعاون» requires a reason; the owner is reminded before موعد المحادثة القادمة.

## S3 — التسعير والتعاقد والفوترة [SAL §17 المرحلة الثالثة] (built 2026-11-12)

Defaults in force (DECISIONS §20): Q1 limits unset → every discount needs the executive; Q4 option A; Q5 mailbox adapter disabled; Q6 price list filled from the screen.

1. **Manager (sultan)** → «قائمة الأسعار»: the matrix card says «حدود الخصم غير محددة». Add «حديد» (مادة، طن، 1,800 ر.س); add a future price (valid from next month) — the current price stays; add a weekly market price; open the item name → history of prices and market rows (nothing editable).
2. **Rep (reem)** → «عروض الأسعار» → «عرض سعر جديد»: pick the customer, add «كرتون» ×10 with 5% discount and «زيارة جمع» ×4, press «احتساب» → totals and «الاعتماد المطلوب: المدير التنفيذي» (limits unset). Save → the quote page (QUO-…), internal columns (list price, discount) visible to the owner; «إرسال للاعتماد» → the executive gets «عرض سعر بانتظار اعتمادك».
3. **Executive (abdullah)** → the same quote → «اعتماد» (sultan cannot while the limits are unset; reem never can). Reem gets «اعتماد أو رفض عرض السعر»; the page shows «اعتمده عبدالله…».
4. **Rep** → «وثيقة العميل» (net prices only) → «إرسال للعميل»: enter the email → the message is saved in the customer file as an unsent draft and a «فتح في برنامج البريد» button appears (mailbox adapter disabled); the opportunity moves to «عرض سعر مرسل». Then «تسجيل رد العميل»: «مرفوض» needs a reason from the list; «قيد التفاوض» → «نسخة جديدة» (v2); «مقبول» with the signed file → أمر البيع SO-… appears on the quote and the linked request moves to «تمت موافقة العميل».
5. **Finance (shahad)** → «الفواتير والتحصيل» → «تسجيل فاتورة صادرة»: choose «أمر بيع», paste the sales-order id → «تعبئة من المصدر» shows the order's lines and totals and «المتبقي غير المفوتر». Change the quantity to half and type the external number and dates: the totals now differ from the source, so «سبب الفرق» becomes required (e.g. «فاتورة الدفعة الأولى») → INV-… with the customer's legal data, «بانتظار الإرسال» for e-invoicing, and the order shows «مفوتر جزئياً». Reem gets «إصدار فاتورة جديدة» (with the reason) and sees «يختلف عن المصدر» on the invoice row. Register a second invoice: the prefill is the remainder; typing more than it is refused; the order becomes «مفوتر». «تسجيل سداد» on each → the order closes only when both are «محصل بالكامل». Reem sees the invoices read-only; majed does not see them.
6. **Admin** → «الإعدادات» → «المبيعات»: set `sales.discountLimitBp` rep 500 / manager 1500 → a 3% discount now auto-approves, 10% goes to sultan, 20% to abdullah.
7. **Rep** → «العقود الدورية» → «عقد جديد» 2026-01-01 → 2026-12-31 with items and pickup dates: «سنة أو أكثر» badge; press «تم» on a schedule date → the dialog asks for the quantities per item (leave empty = one visit per «زيارة» item); «لم يتم» for a missed one; the certificate button appears from 2026-10-02 (90 days before the end); «إصدار شهادة تعاون» → CRT-… → «إرسال» (draft + mail client). The seeded contract for مدارس الرواد is already in that window. On 2027-01-02 the daily job marks it «منتهي»; «تجديد العقد» creates the next one linked to it.
8. **Finance (shahad)** → «تسجيل فاتورة صادرة» → «عقد دوري»: paste the contract id and the month → «تعبئة من المصدر» lists the completed dates of that month and the lines = contract items × recorded quantities at the agreed prices → save → the contract page marks those dates «مفوتر» (locked; they cannot be changed or invoiced again) and the «الفواتير» link shows the contract's invoices. Prefill the same month again → «لا توجد مواعيد منفَّذة غير مفوترة في هذه الفترة».
9. **Manager (sultan)** → his own quote with a 10% discount (limits set as in step 6) → «إرسال للاعتماد»: the required level was «مدير المبيعات», but he is its only holder, so the quote shows «صُعِّد … إلى المدير التنفيذي» and abdullah gets the request; sultan cannot approve it. Abdullah approves → «اعتُمد بصلاحية: المدير التنفيذي». Abdullah may also approve reem's manager-level quotes as the higher authority.

## S4 — الإدارة والمتابعة [SAL §17 المرحلة الرابعة] (built 2026-11-13, branch `sales-s4`)

The seed adds a cardboard sale invoiced and fully collected this month, a weekly market price, monthly targets (reem's changed once with a reason) and a discussion with Finance on شركة الخليج للتغليف.

1. **Manager (sultan)** → «لوحة تحكم المبيعات»: the five groups for the department and the KPI strip. Press «العملاء الجدد» → the customers list opens with the banner «تصفية من اللوحة: أُضيف من … إلى …» and the same count; «إزالة التصفية» shows them all. Press «الفواتير غير المسددة» → the invoices list filtered to unpaid. The budget card shows the revenue and «لا توجد بيانات مالية بعد» for spent and remaining.
2. **Manager** → «مؤشرات الأداء»: the five KPIs with target and status; the conversion target 40% and collection 45 days come from the settings; revenue is before VAT; «متوسط سعر الطن حسب المادة» compares كرتون with the market price. Pick reem, then a service → the numbers narrow.
3. **Manager** → «المستهدفات»: reem's target shows v2; «السجل» lists v1 → v2 with «إضافة عقد شركة الخليج للتغليف». «تعديل» without a reason is refused; with a reason → v3 and reem gets «تحديث مستهدفك الشهري». «سحب المستهدف» needs a reason; the row moves to «مستهدفات مسحوبة» with its full history. «مقارنة بين الأشهر» shows several months.
4. **Rep (reem)** → «لوحة تحكم المبيعات» / «مؤشرات الأداء» / «المستهدفات»: only her own numbers and her own targets; no edit buttons.
5. **Rep** → customer شركة الخليج للتغليف → «النقاشات»: the seeded thread with Finance and its reply. «فتح نقاش مع قسم» → التشغيل, a subject, details, a photo → the Operations members get «وجود مشكلة أو استفسار من قسم آخر». **An Operations employee** → «النقاشات بين الأقسام» → «وارد قسمي» → reply → the state becomes «قيد المعالجة» automatically; «تم الحل» asks for the action taken. **Rep** → «إغلاق النقاش» → read-only. Majed cannot open reem's thread (404).
6. **Rep** → customer → «جدولة اجتماع»: type «حضوري», place, tick «يحتاج مشاركة قسم التسويق» → the organizer becomes required → save → the Marketing members get «فعالية تحتاج دعم قسم التسويق» once. Open the meeting → «تحديث الحالة» → «تم», the outcome and the next follow-up → the customer's log shows the outcome «من التقويم» and the next follow-up moves.
7. **Manager** → «الإجراءات والتعليمات» → «رفع مستند» (PDF only) → «رفع نسخة جديدة» keeps the old one in «سجل النسخ»; reem reads and downloads, cannot upload.
8. **Manager** → «المهام والزيارات»: the department's open tasks and the next 30 days of meetings and visits, per employee.
